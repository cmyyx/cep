# MaaEnd 基质导入设计

状态：可编辑预览、确定导入和武器图标已实现并通过验证。

需求来源：[CEP issue #116](https://github.com/cmyyx/cep/issues/116)。
外部格式：[MaaEnd EssenceInventory.json Schema](https://github.com/MaaEnd/MaaEnd/blob/v2/tools/schema/essence_inventory.schema.json)。

## 已确认规则

1. 导入结果用于批量勾选 CEP 的“已有基质”状态。对文件中出现的适配武器，只要存在完美匹配基质，就视为已有基质。
2. 不进行数量分配。一组基质适配多把武器时，所有适配武器均可勾选；不因数量少于适配武器数而保留部分武器的刷取需求。
3. 不设置词条等级门槛。等级不参与已有基质判定。
4. 保留已有数据，尤其是手工勾选和自定义武器的已有基质状态；展示导入变更和冲突。不判断是否重复导入同一文件，不累加数量。此规则修正了上一轮直接替换全部已有基质标记的提案。
5. 仅更新已有基质勾选，沿用现有规划和隐藏设置。已知武器 ID 正常处理，未知 ID 跳过并报告；格式错误或非空文件的全部武器 ID 都未知时，拒绝导入并保留原数据。选择文件只生成预览，用户可以取消本次新增武器的勾选，点击“确定导入”后才写入；原有勾选不受调整影响。

## 代码事实

- `src/types/essence-settings.ts` 的 `EssenceAccount.essenceStatus` 是按武器 ID 存储的布尔标记，适合本需求。
- `src/stores/useEssenceSettingsStore.ts` 将当前账号标记与 `accounts` 同步维护，并持久化；云同步使用同一组账号标记。
- `src/stores/useMatrixStore.ts` 的 `getPlansForSelection` 不读取已有基质标记。现有“隐藏已有基质”设置控制列表和方案展示，不是求解器输入过滤。
- MaaEnd 文件提供适配武器 ID、等级和数量，没有账号标识。空数组是完整扫描后没有符合条件的库存。

## 已确认的保留和差异语义

现有标记没有来源信息，无法区分手工勾选与之前文件导入的勾选。用户已确认保留全部旧勾选，包括之前导入的标记。

最终规则：新标记为旧标记与用户在预览中确认的本次导入适配武器的并集。旧勾选未出现在新文件中时，列为“本次扫描未发现，已保留”的差异，不自动取消；自定义武器单独说明不在 MaaEnd 文件覆盖范围内。合法空数组不新增勾选，保留旧勾选并显示扫描差异。

例如旧勾选 A、新文件包含 B：结果为 A、B 均勾选；B 为新增，A 为未在本次扫描中发现但保留。无须增加手工与导入的来源区分。

## 实现方案

解析并校验文件，提取适配武器 ID 的并集，批量更新当前游戏账号的已有基质标记。数量和等级只用于校验外部文件结构，不参与匹配。变更报告包含新增、已勾选且本次仍存在、未在扫描中出现但保留、自定义武器保留、未知武器。

复用现有账号、持久化和同步路径，不修改规划算法，不持久化原始库存或新增标记来源字段。每次导入都重新解析并生成本次报告，不识别文件身份；同一文件重复导入时，新增数量自然变为零。

入口放在基质规划页顶部账号选择旁。选择文件后展示目标账号和可编辑变更预览；点击“确定导入”后保存并展示实际结果，不增加文件去重步骤。

### 1. 文件解析与校验

新增 `src/lib/maaend-essence-import.ts` 及对应 `.test.ts`，将未知输入交给 zod 校验，不以类型断言代替验证。

对齐当前官方 Schema：顶层数组；组内必须包含非空且无重复的 `weapon_ids` 及非空 `essences`；武器 ID 符合 `^wpn_[a-z0-9_]+$`；等级严格为三个整数，范围分别为 1–6、1–6、1–3；数量为正整数；组与基质记录不接受 Schema 以外的字段。等级和数量合法后即忽略其匹配意义。不同组之间重复出现的武器 ID 取并集。

以 CEP 静态武器目录识别已知 ID，不用翻译后的武器名、图标 ID 或自定义武器词条推断适配关系。格式合法但未知的 ID 收集并报告；非空文件没有任何已知武器时整份拒绝。合法 `[]` 按空扫描结果处理。

JSON 语法错误、结构错误、文件读取失败均在写入状态之前终止，不产生部分导入。校验信息转换为 next-intl 翻译文案，不将 zod 的原始英文错误直接展示给用户。

### 2. 一次性更新当前账号

在 `src/types/essence-settings.ts` 增加批量导入动作类型，在 `src/stores/useEssenceSettingsStore.ts` 实现一次性合并及差异报告，并补充现有 store 测试。

基于写入时的最新状态计算：

```text
old = 原有 true 标记的武器集合
incoming = 用户确认保留在本次导入中的 CEP 已知适配武器集合
new = old ∪ incoming
added = incoming − old
consistent = incoming ∩ old
retainedMissing = old 中不在 incoming 的正式武器
retainedCustom = old 中的自定义武器
```

通过单次 Zustand `set` 同步更新目标账号和当前账号标记镜像，复用现有 `patchActiveAccountMarks` 维护方式；不得循环调用单武器 `setEssenceStatus`，避免多次持久化和中间状态。将新动作保留在 persist 的恢复合并中。

新增只读 `previewEssenceMarks` 动作，与写入动作共享差异计算，预览不触发持久化或云同步。文件读取开始时记录目标账号 ID；若读取完成或确定导入时账号已切换或删除，拒绝本次应用并提示重新选择文件，避免写到其他账号。武器拥有状态、备注、其他账号、选中目标和隐藏设置不参与更新。

复用 `essence-settings` 持久化和现有账号云同步协议；没有新增持久化字段，因此无须升级云同步数据结构或改后端。完全无新增的导入仍生成结果报告，可直接返回原状态以避免无意义的持久化与同步。

### 3. 导入入口与结果

新增 `src/components/essence/maaend-essence-import-dialog.tsx` 和对应 `.test.tsx`，在 `src/app/[locale]/essence-planner/page.tsx` 顶部账号选择旁接入。

用 Shadcn/UI 的 Button、Dialog、Input、Checkbox 和可折叠列表组装，遵循 DESIGN.md，兼顾移动端宽度。文件选择使用可见的 Shadcn Input，不直接查询或操作 DOM。新增 `maaend-essence-weapon-row.tsx`，复用 `RarityFrame` 展示图标及名称，使用武器 `iconId` 获取游戏图标；自定义和未知武器显示回退图标。预览中的新增项可取消或恢复勾选，原有标记只读保留；确定后显示实际导入结果。正式武器使用项目现有武器翻译来源。

“未在扫描中发现”是扫描差异提示，不表达“基质已经丢失”，也不提供自动取消勾选动作。合法空扫描和重复导入均显示明确的结果，用户可以关闭弹窗后继续正常手工修改勾选。结果报告属于本次组件交互状态，无须持久化。

所有新增 UI 文案补齐 `src/messages/zh-CN.json`、`en.json`、`ja.json`、`zh-TW.json`。导入错误为本地文件校验结果，无须伪造服务端 ApiError；如果实现选择使用 ApiError，则必须按 AGENTS.md 同时补齐错误码联合类型、映射和四语言文案。
